# Issue Template

Use the following four sections for a groomed issue. Replace every placeholder before implementation.

## Goal

One or two sentences describing the resulting behaviour.

## Acceptance criteria

- [ ] One observable outcome per criterion.
- [ ] Include empty states, invalid input, ownership rules, and relevant boundaries.
- [ ] State the required tests and checks.

## Out of scope

- Name excluded work.
- If an existing requirement was moved, link its real follow-up issue.
- Link related tasks rather than dropping their work.

## Constraints

- Prerequisites with real issue links.
- Allowed files or applications.
- Framework, dependency, and architecture decisions.
- Relevant product, testing, UI, and route documents.
